# Промт для нейросети: «Diamond Shell» — оконная оболочка на своём движке

> Скопируй всё, что ниже разделителя, в нейросеть-исполнитель (Claude / GPT / Gemini в режиме агента с доступом к репозиторию). Промт написан под конкретный репозиторий `Diamond_engine` и его реальный API.

---

## Роль

Ты — Android-инженер, который пишет нативный код для сверхлёгкого движка. Ты работаешь в репозитории `Diamond_engine` (ветка `main`, Java + C/C++/CMake + Gradle, без AndroidX). Ты не переписываешь движок с нуля и не добавляешь сторонних библиотек: всё делается на том, что уже есть в репозитории, плюс фреймворк Android.

## Задача

Сделать **«Diamond Shell»** — полноценную оконную оболочку внутри Android-приложения, по духу похожую на десктопную ОС (референс: веб-проект «Windows 12»), но **реализованную нативно**: никакого WebView, никакого HTML/CSS/JS, никакой разметки в духе `index.html` из референса.

Итог — приложение, которое после запуска показывает: рабочий стол с обоями и иконками, панель задач по центру с кнопкой «Пуск», перетаскиваемые и изменяемые по размеру окна с привязкой к краям, меню «Пуск» с поиском, быстрые настройки, центр уведомлений и 3–4 работающих приложения внутри окон.

## Жёсткие ограничения (нарушение = провал задачи)

1. **Никакого WebView, HTML, CSS, JavaScript.** Оболочка рисуется нативно.
2. **Никакой AndroidX, Compose, RecyclerView, Material Components.** Только `android.*` из framework и уже существующий код. В `app/build.gradle` блок `dependencies` остаётся пустым. Пункт `android.useAndroidX=false` в `gradle.properties` не меняется.
3. **Бюджет APK — 12 МБ.** Сейчас debug-APK на обе ABI ≈ 5.7 МБ. Оболочка должна добавиться максимум на ~1.5 МБ. Новые ассеты — только векторные (`VectorDrawable`) или сгенерированные в коде. Никаких PNG-наборов иконок и никаких шрифтов в `assets/`.
4. **minSdk 21.** Всё, что новее (`RenderEffect`, `BlurMaskFilter` на железе, `WindowInsetsController` и т.п.), — только под проверкой `Build.VERSION.SDK_INT` с осмысленным фолбэком. Приложение обязано запускаться и работать на Android 5.0.
5. **Никаких новых нативных зависимостей.** `libengine.so` остаётся единственной `.so` в APK.
6. **Нельзя ломать существующее.** `python3 tools/check_repo.py` и `python3 tools/check_gles_shaders.py` должны проходить. CI-шаг «Verify APK» сверяет число экспортированных JNI-символов с числом `native`-методов в `NativeBridge.java` — если добавляешь нативный метод, добавляй и реализацию, и наоборот.

## Что уже есть в движке (используй это, не изобретай)

Публичный C-ABI (`app/src/main/cpp/include/diamond.h`, обёртка в Java — `model/Engine.java` и `jni/NativeBridge.java`):

| Возможность | API |
|---|---|
| Жизненный цикл | `diamond_init(filesDir, cacheDir, apiLevel)`, `diamond_shutdown()` |
| Поверхность | `diamond_attach_surface(ANativeWindow*, w, h)`, `diamond_detach_surface()`, `diamond_surface_resized(w, h)` |
| Сцена | `diamond_add_node(type, parent, name)`, `diamond_add_primitive(prim)`, `diamond_node_set_transform(id, float trs9[9])`, `diamond_node_set_color(id, rgba)`, `diamond_delete_node(id)` |
| Типы узлов | `DIAMOND_NODE_EMPTY=0`, `DIAMOND_NODE_SPRITE=1`, `DIAMOND_NODE_MESH=2` (света и камеры как отдельных типов нет) |
| Примитивы | `DIAMOND_PRIM_QUAD=0`, `CUBE=1`, `PYRAMID=2`, `GRID=3` |
| Камера | `diamond_camera_orbit`, `camera_pan`, `camera_zoom`, `camera_reset`, `camera_focus_node` |
| Бэкенды | `DIAMOND_RENDER_GLES3=1`, `VULKAN=2`, `GLES2=3`, `HYBRID=4`; `diamond_set_render_mode(mode)` с авто-фолбэком на GLES3 |
| Режим вида | `diamond_set_view_mode(DIAMOND_VIEW_2D=0 / DIAMOND_VIEW_25D=1 / DIAMOND_VIEW_3D=2)` |
| Ввод | `diamond_touch(phase, pointerId, x, y)`, `diamond_button(index, down)`, `diamond_joystick(x, y)` |
| Блочная логика | `diamond_block_add(kind, node, param, x, y, text, a, b, c)`; виды `DBLOCK_ON_START=0 … DBLOCK_END=90` (`app/src/main/cpp/include/diamond/dlogic.h`) |
| Документы | `diamond_save_diamond(path)`, `diamond_load_diamond(path)`, `diamond_serialize()`, `diamond_deserialize(bytes)` |
| Статистика | `diamond_get_stats(buf, cap)` → строка `TAG\|fps\|frame_ms\|rss_mb\|nodes\|blocks` |
| Лог | `diamond_log_write(tag, msg)`, `diamond_log_poll(since, buf, cap, out)` |

**Ключевой факт: движок не умеет рисовать текст и 2D-интерфейс.** В `render/` нет ни шрифтов, ни атласа глифов, ни спрайт-батчера для UI. Это не баг, который нужно править в первую очередь, а ограничение, которое определяет архитектуру (см. ниже).

Существующий UI-код (образец стиля и приёмов): `ui/EditorActivity.java`, `view/ViewportView.java` (`SurfaceView`, тач-жесты, HUD-оверлей через `Canvas`), `ui/SceneTreeAdapter.java` (`BaseAdapter`).

## Архитектура, которую нужно реализовать

### Слой 1. Оболочка — на `android.graphics.Canvas`

Вся «хромированная» часть (обои, панель задач, меню «Пуск», окна: заголовки, рамки, кнопки, тени) рисуется одним кастомным `View`, который целиком контролирует свою отрисовку. Это даёт:

- текст бесплатно (`Paint` + `StaticLayout`) — главное, чего нет в движке;
- корректную работу со шрифтами, RTL, масштабом системного шрифта;
- `hardwareAccelerated` уже включён в манифесте, так что рисование идёт через GPU.

Обязательные требования к этому слою:

- **Никаких `View` на каждое окно.** Окна — это структуры в памяти (`ShellWindow`), а не иерархия вьюх. Иначе на телефоне с 1 ГБ и 20 окнами получится «дёрганый» интерфейс.
- **Перерисовка по расписанию, а не «на всё».** `invalidate()` только когда что-то изменилось: анимация, скролл, фокус, ввод. В покое оболочка не должна потреблять CPU.
- **Один `Paint` на тип, переиспользуемый.** Никаких `new Paint()` в `onDraw`.
- **Кэш тяжёлых частей.** Размытие/тень под окном — либо в `Bitmap` (пересобирается только при изменении размера/положения), либо отсутствует на API < 31.

### Слой 2. Приложения — на движке

Само содержимое окон (3D-сцена, превью модели, игра) рендерится `libengine.so` в отдельный `SurfaceView`, вложенный в окно как «содержимое». Правила:

- `SurfaceView` — только там, где реально нужен движок. Текстовый редактор и калькулятор не должны занимать GPU-поверхность.
- Максимум **одна активная GL-поверхность** за раз (плюс `ViewportView` редактора, если он открыт). Остальные окна при потере фокуса показывают свой последний кадр как `Bitmap`-снимок и освобождают поверхность. Это критично для памяти на «картофельных» телефонах.
- Прозрачность и z-order между Canvas-слоем и `SurfaceView` в Android ненадёжны. Поэтому: **`SurfaceView` не может пересекаться с другими `SurfaceView`**, а окна-приложения при перекрытии другим окном прячут поверхность и показывают снимок.

### Слой 3. Композиция

`ShellRootView` (Canvas, рисует всё оформление) + один `SurfaceView` сверху для активного 3D-приложения, позиционируемый ровно в прямоугольник окна. Всё остальное — рисование.

## Что именно сделать (функциональные требования)

### 1. Рабочий стол
- Обои: градиент, сгенерированный кодом (никаких картинок в APK), с медленной анимацией сдвига; статичный вариант при отключённых анимациях.
- Сетка иконок: выравнивание по левому краю, две колонки-подписи максимум, обрезка длинных имён многоточием.
- Тап — выбор; второй тап (или дабл-тап) — запуск; долгое нажатие — контекстное меню (Открыть / Переименовать / Удалить).
- Перетаскивание иконки с магнитной сеткой; позиция сохраняется в настройках.
- Пустое место: рамка выделения (rubber band), ПКМ/долгий тап — меню (Обновить, Параметры экрана, Вставить).

### 2. Окна
- Заголовок: иконка, название, кнопки «свернуть / развернуть / закрыть» размером не меньше 40×40 dp.
- Перетаскивание за заголовок, изменение размера за 8 краёв и углов (зоны захвата 12 dp, вне видимой рамки).
- Минимум/максимум/восстановление с запоминанием прежних границ; двойной тап по заголовку — максимум.
- **Привязка (snap):** перетаскивание к левому/правому/верхнему краю показывает полупрозрачный предпросмотр и по отпусканию занимает половину, четверть или весь экран. Набор раскладок — как в референсе: ½, ⅓+⅔, ½+¼+¼, 2×2.
- Фокус: активное окно поднимается, неактивные теряют насыщенность заголовка. Z-order — массив, не `bringToFront()`.
- Границы окна всегда внутри рабочей области (без ухода под панель задач), с учётом выреза экрана и `WindowInsets`.
- Состояние всех окон (позиция, размер, состояние, приложение) переживает поворот экрана. **Движок не перезапускается при повороте** — `android:configChanges` уже включает `orientation|screenSize`, используй это.

### 3. Панель задач
- По центру: кнопка «Пуск», закреплённые приложения, разделитель, запущенные приложения.
- У запущенного приложения — индикатор активности (полоска под иконкой), у активного — расширенный.
- Тап — фокус/запуск, повторный тап по активному — свернуть, долгое нажатие — меню (Закрыть, Прикрепить, Развернуть).
- Справа: индикаторы (сеть, звук, батарея) с реальными значениями из системы (`BatteryManager`, `AudioManager`) и часы.
- Скрытие/показ по тапу в центр и по свайпу вверх с нижнего края; режим «автоскрытие» опционален.
- Высота панели ≈ 52 dp, скругления ≈ 16 dp, полупрозрачный фон.

### 4. Меню «Пуск»
- Поиск по названию приложения и по ключевым словам; клавиатурная навигация (стрелки, Enter, Esc).
- Сетка закреплённых приложений, список всех приложений, блок «Рекомендуемые» (последние открытые документы).
- Внизу: аватар пользователя и кнопка питания с меню (Заблокировать, Спящий режим, Завершение работы, Перезагрузка).

### 5. Быстрые настройки и уведомления
- Плитки: Wi-Fi, Bluetooth, «В самолёте», экономия заряда, ночной свет, тёмная тема, «Не беспокоить», анимации.
- Слайдеры яркости и громкости — реально применяются (`WindowManager.LayoutParams.screenBrightness`, `AudioManager`).
- Тёмная/светлая тема переключается на лету, без перезапуска активности.
- Уведомления: список с временем, иконкой, кнопкой закрытия и «Очистить все».

### 6. Приложения (минимум 4, все рабочие)
1. **Проводник** — список файлов из `getFilesDir()` / `getExternalFilesDir()`, навигация по папкам, открытие `.diamond` в редакторе движка, удаление, переименование.
2. **Настройки** — тема, акцентный цвет, обои, размер иконок, анимации, вертикаль панели задач, выбор бэкенда рендера (GLES3 / Vulkan / GLES2 / Hybrid) с реальным переключением через `diamond_set_render_mode` и показом причины отказа.
3. **Блокнот** — открытие/сохранение `.lua`, подсветка ключевых слов Lua, проверка через `diamond_luac_check` с показом строки и текста ошибки.
4. **3D-просмотр** — окно с живой сценой движка: `diamond_add_primitive`, вращение камеры жестами, переключение 2D/3D, строка статистики из `diamond_get_stats` (fps / память / узлы).

Все приложения — это реализация общего интерфейса:

```java
public interface ShellApp {
    String id();                 // стабильный идентификатор
    String name();               // отображаемое имя
    int icon();                  // R.drawable.* (вектор)
    int defaultWidthDp();        // 320..640
    int defaultHeightDp();
    boolean singleInstance();    // повторный запуск фокусирует окно
    View createView(ShellWindow window, LayoutInflater inflater);
    void onResize(ShellWindow window, int w, int h);   // перекомпоновка
    void onPause(ShellWindow window);                  // освободить GPU
    void onResume(ShellWindow window);                 // восстановить кадр
    boolean onBack(ShellWindow window);                // true = обработано
}
```

Регистрация — в статическом реестре, без рефлексии и без DI-фреймворков.

## Производительность (это не пожелание, а критерий приёмки)

- 60 fps при 6 открытых окнах на устройстве уровня 2018 года; 30 fps на «картофельном» телефоне (2 ядра, 2 ГБ).
- Потребление памяти оболочкой ≤ 60 МБ RSS; в покое процесс не должен просыпаться чаще 1 раза в секунду (никаких `postInvalidateDelayed(16)` в цикле).
- Ноль аллокаций в `onDraw` — проверь и укажи в комментариях, что кэшируется.
- Время запуска до появления рабочего стола ≤ 1.5 с на холодную.

## Чего делать нельзя

- Вставлять HTML/JS/CSS любым способом, включая `WebView` с локальными ассетами, `Html.fromHtml` для вёрстки и `res/raw` с разметкой.
- Добавлять AndroidX «только для RecyclerView» или «только для анимаций». Всё есть во framework.
- Создавать по `View` на каждую иконку, строку списка или окно.
- Класть в APK картинки и шрифты вместо векторов и canvas-рисования.
- Использовать `BlurMaskFilter`/`RenderEffect` без проверки API и без фолбэка.
- Перезапускать движок при смене ориентации.
- Менять публичный C-ABI в `diamond.h` без нужды; если нужен новый вызов — добавь его и в `NativeBridge.java`, иначе CI-проверка символов упадёт.
- Оставлять `TODO` в готовом коде. Если что-то не сделано — так и напиши в комментарии с причиной.

Пока промт писался, проверка соответствия констант вскрыла четыре настоящих бага в текущем коде — они исправлены в том же коммите. Если нейросеть-исполнитель увидит эти места, пусть знает, что они уже закрыты:

| Место | Было | Стало |
|---|---|---|
| `NativeBridge.VIEW_2D/25D/3D` | 1 / 2 / 3, а C принимает 0..2 → кнопка «3D» не делала ничего | 0 / 1 / 2 |
| `NativeBridge.PRIM_CUBE/QUAD` | куб и квад перепутаны → «Cube» добавлял квад | порядок как в `DiamondPrimitive` |
| `NativeBridge.ERR_*` | `ERR_MEMORY=2`, `ERR_IO=3`, `ERR_GPU=7`, `ERR_UNSUPPORTED=6` — не совпадали с C | точное соответствие `DiamondStatus` |
| `tools/check_repo.py` | расхождение констант не проверялось вообще | `check_enum_mirrors()` сверяет все 34 константы |

Мораль для исполнителя: **не дублируй константы вручную без проверки.** Если добавляешь новый enum — добавь его и в `check_enum_mirrors`-совместимую форму, иначе следующее расхождение снова будет молчаливым.
